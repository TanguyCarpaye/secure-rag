=== Requirements Overview

In high-tech industries (aeronautics, aerospace, defense in the Occitanie region), design offices, engineering departments, and support functions handle massive volumes of critical documentation: technical specifications for civil and military programs, certification files, maintenance manuals, flight test reports, and lessons-learned databases.

The use of foundation models (FM) via a retrieval-augmented generation (RAG) architecture is a major driver of productivity. However, the information security policy (PSSI) of industrial clients strictly prohibits the transmission of confidential data over the public Internet and any risk of models being retrained by third parties.

This document outlines the design of a secure and isolated enterprise RAG platform.

==== Problem Summary and Statement of Intent
The architectural challenge lies not in software application development, but in system architecture, infrastructure isolation, and access governance. The system provides a managed cognitive assistance service without any data flows leaving the private corporate network.

==== Target Functional Capabilities
. Asynchronous ingestion and vectorization : Extraction, chunking, and generation of semantic embeddings for office and technical documents (PDF, Word, Markdown, vectorized diagrams) stored in highly secure environments.
. Hybrid similarity search : Low-latency indexing and contextual retrieval of relevant document passages via a managed vector database.
. Context-aware response generation: Inference using leading Large Language Models such as Anthropic Claude 3.5 Sonnet or Haiku via Amazon Bedrock—powered exclusively by the extracted document context.
. Contextual filtering and automated guardrails: Proactive detection and blocking of prompt injections and jailbreaks, automatic masking of personally identifiable information (PII), and prevention of output outside the approved document domain via Bedrock Guardrails.

=== Quality Goals
Quality objectives constitute the system's defining decision-making criteria. Sealing and intellectual property protection take precedence over any functional trade-off.

|===
|ID|Quality Objective|Category|Description & Validation Metric

|QG-1
|Data Isolation & IP Protection
|Security / Confidentiality
|Zero intellectual property leakage. Processed data is never persisted by model providers nor reused for retraining. Mandatory encryption at rest and in transit via Customer Managed Keys (AWS KMS CMK) with annual rotation and strict segregation of duties.

|QG-2
|Total Network Isolation
|Security / Network
|Zero traffic traverses the public internet. All network paths (ingestion, vectorization, inference) reside in private subnets without Internet Gateways (IGW) or NAT Gateways. Services are consumed exclusively via interface endpoints (AWS PrivateLink / VPC Endpoints).

|QG-3
|Safety & Hallucination Mitigation
|Reliability / Integrity
|Neutralization of prompt injection and jailbreak attempts. Deterministic blocking of out-of-scope enterprise queries via Bedrock Guardrails, along with automated redaction and masking of PII / GDPR-sensitive entities.

|QG-4
|Operational Simplicity & Serverless Model
|Maintainability / Operations
|Zero server administration overhead. Exclusive adoption of fully managed, serverless building blocks (Amazon Bedrock, Amazon OpenSearch Serverless / Aurora PostgreSQL Serverless pgvector). Fully reproducible IaC deployment (Terraform) without persistent custom application hosts.

|QG-5
|Inference Performance & FinOps Governance
|Efficiency / Cost Optimization
|Time to First Token (TTFT) < 1.2 s and overall P95 latency < 4.0 s on 20,000-token contexts. Granular tracking of input/output token consumption using AWS Cost Allocation Tags paired with budget alert thresholds.
|===
