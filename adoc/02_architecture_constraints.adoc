== Architecture Constraints

This section outlines the non-negotiable boundaries governing the Secure Enterprise RAG Platform. Architectural decisions must strictly adhere to these rules.

=== Technical Constraints

The platform enforces a zero-trust, air-gapped network perimeter.

[cols="2,5", options="header"]
|===
| ID & Constraint | Specification & Rationale

| *TC-1: Serverless*
| Exclusive use of AWS managed services (Bedrock, OpenSearch Serverless, S3). Provisioning VMs (EC2) or Kubernetes nodes (EKS) is forbidden to eliminate OS maintenance.

| *TC-2: Air-Gapped Network*
| Zero public internet transit. No Internet/NAT Gateways. All traffic routes internally via AWS PrivateLink (VPC Endpoints) and S3 Gateway Endpoints.

| *TC-3: Cryptographic Sovereignty*
| Mandatory AWS KMS Customer Managed Keys (CMK) for data at rest and in transit. Default AWS keys are prohibited. Strict annual key rotation.

| *TC-4: Infrastructure-First*
| Zero bespoke application code (e.g., Python middleware). Reliance on native orchestration to minimize attack surface.

| *TC-5: EU Data Residency*
| Primary infrastructure, vector storage, and inference strictly provisioned in `eu-west-3` (Paris).
|===

=== Organizational and Regulatory Constraints

These boundaries guarantee data sovereignty and strict access governance.

[cols="2,5", options="header"]
|===
| ID & Constraint | Specification & Rationale

| *OC-1: Zero Data Retention (ZDR)*
| Strict technical and contractual prohibition of model retraining on corporate data. Ephemeral inference only.

| *OC-2: Regulatory Compliance*
| Multi-tier governance aligned with the EU AI Act, Export Control, and defense/civil dual-use frameworks.

| *OC-3: ABAC & IAM Segregation*
| Dual-control IAM: Strict separation between Cloud Admins and KMS Key Custodians. Document access is enforced via pre-retrieval vector-level Attribute-Based Access Control (ABAC).

| *OC-4: Auditability Gateways*
| Retrieval pipelines filter based on valid engineering effectivities and document revisions. Formal alignment with the AWS Well-Architected Framework.
|===

=== Conventions and Standards

[cols="2,5", options="header"]
|===
| ID & Convention | Specification & Tooling

| *CON-1: DevSecOps & IaC*
|  HashiCorp Terraform (>= 1.8). Automated CI/CD pipelines with mandatory static security analysis and linting.

| *CON-2: FinOps Tagging*
| Mandatory AWS Cost Allocation Tags (`Project`, `Environment`, `DataClassification`, `CostCenter`). Untagged resources are automatically quarantined.
|===
